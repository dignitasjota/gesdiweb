La pregunta que más nos hacen al firmar un proyecto: **¿WordPress
o Astro?** La respuesta corta es "depende". La larga, este post.

## Cuándo conviene WordPress

- El cliente edita contenido **constantemente** y necesita un panel
  visual.
- Hay un equipo de marketing acostumbrado a Gutenberg/Elementor.
- El proyecto necesita **WooCommerce** sí o sí.
- El presupuesto es ajustado y hay un ecosistema de plugins maduro
  para lo que se necesita.

## Cuándo conviene Astro

- El editor de contenidos es técnico (o no hay editor — tú lo
  mantienes).
- **El SEO técnico es crítico** y no puedes permitirte que un plugin
  ralentice la web.
- El proyecto es mayoritariamente estático (catálogo, web
  corporativa, blog).
- Quieres **rendimiento de fábrica** sin pelearte con caches.

## Lo que casi nadie cuenta

WordPress no es lento porque sí. Lo es porque acumula plugins,
queries de BD en cada request y temas pesados. Bien configurado
puede ir muy bien — pero "bien configurado" implica disciplina
constante.

Astro es rápido porque no hay nada que ralentizar. Si no tienes JS
en cliente, no hay JS en cliente. Si no haces queries en runtime,
no las hay. Es un punto de partida más bajo.

## Conclusión

Para gesdiweb usamos los dos: WordPress cuando el cliente lo
necesita, Astro cuando podemos. Esta misma web está hecha en Astro,
y sí, podemos editarla cómodamente desde nuestro editor.
