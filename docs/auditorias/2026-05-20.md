## Diagnóstico — qué falla y por qué

### 1. Contraste — `#a7a7a7` sobre `#fafaf8` (ratio 2.3:1)

El token `--color-mute: #a7a7a7` se usa como color de texto principal en eyebrows monospace (`.process-eyebrow`, `.services-eyebrow`, `.portfolio-eyebrow`, `.blog-recent-eyebrow`), metas (`.bc-date`, `.pc-sub`, `.p-num`), descripciones (`.p-desc`) y tags (`.p-tags span`). Falla AA 4.5:1.

En `docs/convenciones.md` se documentaba que `#a7a7a7` "solo se usa para detalle decorativo, nunca para texto principal" — pero el rediseño Claude Design lo aplicó como color de meta-texto, lo que sí es texto a efectos de WCAG.

### 2. Contraste — `#76c2da` (brand) sobre `#fafaf8` (ratio 1.91:1)

El patrón `<em>` dentro de h1–h4 (Instrument Serif italic + brand) usa el brand directamente. Falla incluso el umbral de 3:1 para texto grande (≥18pt o ≥14pt bold).

Mismo problema en metas pequeñas con color brand: `.bc-cat`, marquee em variants.

### 3. Contraste — cookie banner botón "Aceptar todas" (ratio 2:1)

`#ffffff` sobre `#76c2da` en un botón pequeño (11px). Falla AA 4.5:1 incluso aceptando que sea texto pequeño.

### 4. `aria-hidden-focus` — cookie banner oculto con descendientes enfocables

`#cookie-banner` se marca con `aria-hidden="true"` mientras está colapsado, pero sus `<button>` hijos siguen en el árbol de focus. Lectores de pantalla + teclado los anuncian/alcanzan aunque están "ocultos".

**Fix correcto:** atributo `inert` (oculta de focus y AT en bloque), no `aria-hidden`.

### 5. `heading-order` — `<h3>` sin `<h2>` previo

Lighthouse marcó esto en home, servicios/diseno-web, portfolio/asucar-valencia, contacto y proceso. El detalle solo señala "`<h3>`"; pendiente de localizar exactamente en qué sección rompe la cascada. Probable causa: alguna sección con `<h3>` decorativo sin h2 que lo agrupe (puede ser el `/blog` listado o el rail derecho del post).

### 6. Performance — `uses-text-compression`, `render-blocking-resources`

Ambos aplican a **todas** las páginas y son responsables del techo de ~92–95 en perf:

- **text-compression:** el server node standalone no aplica gzip/brotli. En producción esto lo resuelve NPM (Nginx) automáticamente. **No es un problema de código.**
- **render-blocking-resources:** la hoja de estilos global se carga blocking. Aceptable para un sitio estático compacto; mejorable con critical CSS inline si quisiéramos rascar puntos.

### 7. Otros perf — `modern-image-formats`, `uses-responsive-images`

Marcados en `/`, `/portfolio`, `/servicios` con score 0.5 en algunos casos. Indican que ciertas imágenes podrían beneficiarse de webp/avif o `srcset` más estrecho. Astro Image ya genera webp; los casos restantes son imágenes del logo o assets que entran sin pasar por `<Image>`.

## Fixes implementados y re-auditoría (misma sesión, 2026-05-20)

Tras el primer pase de la auditoría se aplicaron los siguientes cambios:

### Tokens del sistema de diseño (`globals.css`)

- `--color-muted: #a7a7a7` → `#6b6b6b` (≥ 5:1 sobre `#fafaf8`).
- Token nuevo: `--color-brand-ink: #1d6c83`. Variante oscura del brand para uso en texto (~6.5:1 sobre `#fafaf8`). Se mantiene `--color-brand: #76c2da` para superficies decorativas.
- Selector global `h1 em, h2 em, h3 em, h4 em, .serif-em` pasa de `--color-brand` a `--color-brand-ink`.

### Componentes y páginas

- **Marquee.astro**: variante `--brand` ahora usa texto `--color-fg` (negro) sobre brand. El `em` brand-light pasa a `--color-brand-ink`.
- **BlogRecent.astro**: `.bc-cat` → `--color-brand-ink`.
- **proceso.astro**: `.proc-stat .v`, `.proc-phase-activities .idx`, `.proc-principle .pn` → `--color-brand-ink`.
- **servicios/[slug].astro**: `.svc-deliv-list .num` → `--color-brand-ink`.
- **portfolio/[slug].astro**: enlaces `.case-prose a` y `.case-meta .cm-value a` → `--color-brand-ink`.
- **blog/index.astro**: `.blog-filter button .num` sube opacity de 0.55 → 0.7 para superar 4.5:1.

### CookieBanner

- `aria-hidden="true"` → atributo `inert` (gestionado vía JS con `el.inert = true/false`). Resuelve `aria-hidden-focus`.
- Botón "Aceptar todas": texto blanco → `--color-fg` (negro). Ratio 2:1 → 8.6:1.

### Heading order

Se reordena la jerarquía para que cada heading siga al anterior sin saltos:

- **servicios/[slug]**: `h3` "Lo que incluye" / "Cómo trabajamos" → `h2`.
- **portfolio/[slug]**: `h3` "Caso de estudio" / "Stack técnico" → `h2`.
- **contacto**: tres `h3` del info-side → `h2`. Dos `h4` del FAQ → `h3`.
- **proceso**: `h4` "Qué hacemos en esta fase" → `h3`. Dos `h5` (Entregables / Herramientas) → `h4` para conservar la cadena.
- **blog/[slug]**: `h4` del TOC y los tres `h4` del rail → `h2` (son secciones top-level del documento).

CSS de cada archivo actualizado en paralelo (selectores `h3`/`h4`/`h5` → nuevo nivel) para conservar el estilo visual exacto.
